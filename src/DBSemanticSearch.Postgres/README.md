# DBSemanticSearch.Postgres

PostgreSQL adapter for the DB Semantic Search solution. The project implements the persistence contract defined in `DBSemanticSearch.Core` and uses `pgvector` to store embeddings and order results by cosine distance.

## Responsibilities

- persist texts and embeddings in PostgreSQL;
- perform exact vector searches with the `pgvector` `<=>` operator;
- create and verify the schema on the first operation;
- validate embedding dimensions and values before sending them to the database.

The project does not read environment variables directly and does not choose the authentication method. It receives an already configured `NpgsqlDataSource` through dependency injection from the API, keeping data access separate from application composition.

## Dependencies

- [`DBSemanticSearch.Core`](../DBSemanticSearch.Core) for `ITextRepository`, `TextDocument`, and `SearchHit`;
- [`Npgsql`](https://www.npgsql.org/) for PostgreSQL connections, commands, and pooling;
- [`pgvector`](https://github.com/pgvector/pgvector) as an extension installed on the server.

## Classes

| Class | Description |
| --- | --- |
| [`PostgresTextRepository`](PostgresTextRepository.cs) | Sealed implementation of `ITextRepository`. Receives an `NpgsqlDataSource` and the expected embedding dimension. |

### `PostgresTextRepository`

`InsertAsync` validates the vector, initializes the schema if necessary, and inserts a document with a new UUID. The timestamp is generated by the database and returned as a UTC `DateTimeOffset`.

`SearchAsync` calculates the cosine distance between the requested vector and every document, orders by increasing distance, and applies the specified limit. Ties use the UUID as a deterministic ordering key.

`EnsureSchemaAsync` runs only once per instance. A `SemaphoreSlim` prevents concurrent initialization; after creation, it checks that the column type is exactly `vector(<dimensions>)`.

`FormatVector` rejects vectors with a dimension different from the configured value or non-finite values and uses the invariant culture for numeric serialization.

## Schema

Before the first operation, a PostgreSQL administrator must install the extension in the application database (not just in the `postgres` database):

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

On Azure PostgreSQL Flexible Server, `vector` must be enabled in `azure.extensions`, and installation requires a member of `azure_pg_admin`. The application identity must not be granted this administrative role. The `azd` postprovision hook installs the extension in `semantic_search` using the configured Microsoft Entra administrator.

On the first operation, the repository checks that the extension is installed and creates the table:

```sql
CREATE TABLE IF NOT EXISTS documents (
    id uuid PRIMARY KEY,
    text text NOT NULL,
    embedding vector(<dimensions>) NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);
```

The dimension is a persistent schema constraint. Changing the embedding model requires migrating the column or recreating the table; changing only `EMBEDDING_DIMENSIONS` intentionally causes an error on the first operation.

## Configuration

Data source configuration takes place in [`DBSemanticSearch.Api/Program.cs`](../DBSemanticSearch.Api/Program.cs). When present, `DB_CONNECTION_STRING` takes precedence over the individual variables.

| Variable | Required | Description |
| --- | --- | --- |
| `DB_CONNECTION_STRING` | No | Complete Npgsql connection string, mainly used in local development. |
| `DB_HOST` | Without connection string | PostgreSQL host. |
| `DB_NAME` | No | Database name; defaults to `semantic_search`. |
| `DB_USER` | Without connection string | PostgreSQL role or Microsoft Entra principal name. |
| `DB_AUTH_MODE` | No | `Password` (default), `DefaultAzureCredential`, or `ManagedIdentity`. |
| `DB_PASSWORD` | With `Password` mode | PostgreSQL password. It is not configured in the Azure deployment. |
| `DB_MANAGED_IDENTITY_CLIENT_ID` | No | Client ID of a user-assigned managed identity; the system-assigned identity is used when absent. |
| `EMBEDDING_DIMENSIONS` | Required for the API | Dimension passed to the repository and expected by the `embedding` column. |

All configurations built from separate variables use `SslMode=VerifyFull`.

### Authentication

- **`Password`** uses `DB_PASSWORD` and is suitable for a local PostgreSQL instance.
- **`DefaultAzureCredential`** uses the Azure credential chain and is useful during development with `az login`.
- **`ManagedIdentity`** uses only the host's managed identity. Npgsql requires a token for the `https://ossrdbms-aad.database.windows.net/.default` scope and refreshes it periodically without putting it in the connection string.

The deployment in [`infra`](../../infra) configures PostgreSQL in Microsoft Entra-only mode and sets `DB_AUTH_MODE=ManagedIdentity` on the Function App. The identity is registered as a PostgreSQL role with `pgaadauth_create_principal_with_oid` by the `postprovision` hook; see the [main README](../../README.md#azure-deployment).

## Database permissions

With the current automatic initialization, the application role must be able to:

- connect to the `semantic_search` database;
- use and create objects in the `public` schema;
- read and insert rows in the `documents` table it creates.

The `vector` extension must be allowed in the Flexible Server configuration and created by an administrator during bootstrap. In an environment with administrative migrations, you can pre-create the table and extension and further reduce the application identity's privileges.

If an existing deployment reports PostgreSQL error `42501` for `CREATE EXTENSION vector`, complete the administrative bootstrap in the correct AZD environment:

```powershell
azd hooks run postprovision -e <environment-name>
```

This hook requires Azure CLI authentication as the configured Microsoft Entra administrator and `psql` on `PATH`. It configures the administrator and Function role, temporarily opens a firewall rule for the local client, installs the extension in `semantic_search`, and grants schema permissions. It does not deploy application code. To verify installation, connect to the application database and run:

```sql
SELECT current_database(), extversion FROM pg_extension WHERE extname = 'vector';
```

## Registration

The API registers the data source and repository as singletons:

```csharp
builder.Services.AddSingleton(CreatePostgresDataSource());
builder.Services.AddSingleton<ITextRepository>(serviceProvider =>
    new PostgresTextRepository(
        serviceProvider.GetRequiredService<NpgsqlDataSource>(),
        settings.Dimensions));
```

`NpgsqlDataSource` manages the connection pool and is designed to be shared for the lifetime of the process.
